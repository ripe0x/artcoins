## what ci proves, and what it does not

proves: submodule checkout works on a clean runner (submodules recursive; all gitlinks exist upstream); the repo compiles at the `ci` profile; every contract in the compile set is under EIP-170 at 200 runs; deterministic tests pass; formatting is stable at forge 1.5.0 (assumed, see H10).

does not prove: anything against live state (H5, H6); the default profile builds or tests (H9); scripts execute (no dry run job); ui builds or lints (H15); anything about script-js; that mainnet bytecode equals source (H23); fork tests passed (they pass vacuously). fresh clone: expected to pass if network and nested submodule hosts are reachable; not run here (no github actions access, forge build of the full set is blocked by the sandbox shim).

the `ci` profile inherits `src`, `solc`, `evm_version`, `fs_permissions`, `fmt` from default and only changes the optimizer block. it duplicates `tune` by hand; the two must be kept in sync manually (foundry.toml comment says so).
