# keeper runner, independent review

scope: `keeper/` (every module, abi, Dockerfile, fly.toml, .dockerignore, README), `docs/v2/review/keeper-runner.md`, `CollectFlushKeeperV1.sol`, `CollectFlushKeeperLayer.sol`, `ArtCoinsKeeperV2.sol`, RUNBOOK part 1 actions 2b and 3. read only on the service. proofs: `keeper/test/review-keeper-runner.test.mjs` (8 tests, fake chain, each asserts today's behaviour, a fix flips it).

| run | result |
|---|---|
| `cd keeper && npm ci && npm test` | 49 pass, 0 fail (41 existing incl. the anvil fork integration test, 8 review) |
| `npm audit --omit=dev` | 0 vulnerabilities. one direct dep, `viem` pinned 2.57.3 (noble, scure, abitype, ox, ws, isows below it) |
| node | 22.22.0 local, image `node:22-alpine` |

verdict: the tx shape and the key handling are tight, a bad rpc cannot redirect a tx or change what is signed. the weak spot is spend control: nothing bounds how often a successful run is resent, so any trigger a run does not clear burns the hot key every 10 minutes (KR-01). fix KR-01 and KR-04 before funding the key.

## findings

| id | sev | title | evidence | fix |
|---|---|---|---|---|
| KR-01 | high | a successful run that does not clear its trigger is resent every tick until the key is empty | `runner.mjs:93-100` decides only from the preview, `runner.mjs:176` resets only the weekly timer, no minimum interval after success, no spend budget. LAYER: router due (`decide.mjs:31`) but the simulated burn skipped gives `wBurn 0`, so `argsLayer` sends `doBurn false` (`decide.mjs:87-88`) and `routerWeth` never drops. v2: no `eth_simulateV1` returns null (`chain.mjs:129`) so `doConvert false` forever (`decide.mjs:95`), or convert pacing (`maxStepIn`, `minBlocksBetweenConverts`, `ConvertTooEarly`) leaves `accruedArtCoin` above 10,000. 111: a persistently skipped flush keeps `escrowedEth > 0.05`. a lying rpc can do the same by returning a due preview. proof: tests `KR-01` (LAYER 36 txs in 6 h, v2 6 txs per hour, v2 paced 90 runs in a day) | per keeper minimum spacing between successful runs (runbook cadence: 111 hourly, LAYER daily, v2 hourly) unless the weekly timer is due; a daily gas spend cap per key that stops sending and alerts; treat "due reason not cleared after a successful run" as a soft failure with the revert cooldown; LAYER: drop the `router*_due` reasons when the simulation burned nothing and raise an alert instead |
| KR-01b | high (part of 01) | the LAYER stale floor alert can never fire | README alert rule keys on `StepSkipped` step 5 in receipts, but a burn that skips in simulation is sent as `doBurn false` (`decide.mjs:88`), so the mined tx has no step 5 and the simulation's own `StepSkipped` logs are not read (`chain.mjs:108` keeps only the return value). the loop in KR-01 is silent apart from `quoted` log lines | count "due, simulation burned nothing" as its own result and metric, alert on it |
| KR-02 | medium | min out comes from the same rpc that is trusted for everything else; a 1 wei quote sends `run(true, 0)` | `minOutFromSim` floors `converted * (10000 - bps) / 10000` (`decide.mjs:66-68`): converted 1 gives 0, `args111` then sends `[true, 0]` (`decide.mjs:80-81`). LAYER: `lBought` 1 against `wBurn` 1e18 gives rate 0 with `doBurn true` (`decide.mjs:72-75, 87-88`), router 0x0EB2 then gets minOut 0 (`CollectFlushKeeperLayer.sol:107-115`). proof: test `KR-02` | refuse to convert when the quote is below an independent bound: read the swapper's `floorFor(amountIn)` or the pool spot from a second rpc and require `sim >= spot implied * (1 - 2 * bps)`; never send `doConvert true` with minOut 0; alert when the two disagree |
| KR-03 | medium | v2: one minOut for every swapper, sized by the smallest convert | `argsV2` takes the least nonzero convert (`decide.mjs:96-99`) and the keeper passes it to every swapper (`ArtCoinsKeeperV2.sol:94-99`). a coin with a 1 eth swapper and a 0.001 eth swapper sends the 1 eth convert with a 0.00099 eth floor. proof: test `KR-03` | send `doConvert true` only when max/min of the simulated converts is within `1 + bps`; otherwise `doConvert false` plus an alert (or a per swapper convert path in a later keeper) |
| KR-04 | medium | no stuck tx recovery: a dropped public tx is forgotten and the next run queues behind it at nonce + 1 | after `DROP_AFTER_SECONDS` the in flight entry is cleared (`runner.mjs:45-49`) but the tx stays in the node's pool; `send` signs at the `pending` nonce (`chain.mjs:140`), so each new run is queued behind the stuck one. a base fee above the tx's `maxFeePerGas` (2 x base at send) for over 30 min stacks one more run every 40 min; when fees drop they all mine, with stale minOuts, each paying gas. no fee bump or cancel exists. proof: test `KR-04` (9 runs queued in 6 h, nonces 0 to 8, none mined) | on drop, replace the stuck nonce (same nonce, fees +12.5% or a 0 value self transfer) instead of forgetting it; sign with the `latest` nonce and refuse to send while `pending > latest` |
| KR-05 | medium | public `/healthz` publishes the pending private tx and the tick schedule | `server.mjs:25` returns `inFlight` (hash, nonce, fn, args with the minOut) while the 111 tx sits in the private relay, plus `lastTickAt`, `intervalSeconds`, address, balance, previews, `lastError`. the README claim "chain public data only" is false for a private tx. a searcher learns when the next LAYER and v2 runs (public mempool) will be sent and what floor a private 111 run carries. proof: test `KR-05` | public route returns only `{ok, lastTickAgeSeconds}`; the detail json on a second port bound to the fly private network (`fly proxy`) or behind a bearer token secret. release the public ips by default |
| KR-06 | low | LAYER gas limit times the fee cap exceeds the funding the README prescribes | `GAS_LIMIT.layer` 3.5M (`config.mjs:13`) times `maxFeePerGas` up to 30 gwei is 0.105 eth upfront. a 0.03 eth key cannot send LAYER once `maxFee` passes 8.6 gwei (base about 4 gwei), a 0.05 eth key at 14 gwei. `send_error` has no cooldown, so it repeats every tick | size `MAX_GAS_GWEI` per keeper from `balance / gasLimit`, or skip with a clear `insufficient_funds_for_cap` result; state the real funding need in the README |
| KR-07 | low | `DRY_RUN` parse fails open | only `'1'` and `'true'` are dry (`config.mjs:135`); `TRUE`, `yes`, `on`, `' 1'` run live. proof: test `KR-07` | accept a case insensitive set and refuse to start on any other non empty value |
| KR-08 | low | private relay is opt in and silent when absent; LAYER and v2 always use the public mempool | `PRIVATE_RPC_URL` unset sends 111 publicly with only `privateRpc: null` in the preflight log (`chain.mjs:146`, `app.mjs:35`). `PRIVATE_RPC_KEEPERS` default `111` (`config.mjs:116`), unknown entries such as `v2:CRED` are ignored silently. LAYER burns (200 bps) and v2 converts (100 bps) are sandwichable up to their slippage every run | refuse live mode with 111 enabled and no private url unless `ALLOW_PUBLIC_MEMPOOL=1`; validate `PRIVATE_RPC_KEEPERS`; default all three to the relay when it is set |
| KR-09 | low | owner key refusal is registry only | `ownerAddresses` reads `reg.owner` and contract `owner` fields (`config.mjs:74-79`); `REGISTRY_PATH` env swaps the registry; no constant for 0xCB43…17F9; other privileged eoas (ui payout 0x41c3…6A4) are not refused | also refuse a hardcoded list (owner, payout); refuse a registry without `owner` |
| KR-10 | low | a missing or remounted volume starts from empty state silently | `loadState` returns empty when the file is absent (`state.mjs:15`). the start command creates `/data` on the root fs if the mount is missing (`Dockerfile:19`). effect: every keeper runs on each restart (weekly reason), the in flight tx is forgotten (feeds KR-04) | write a marker on first run and refuse to start without the state file unless `ALLOW_FRESH_STATE=1`; check `/data` is a mount point |
| KR-11 | low | lost settlement paths | (a) "nonce used" clears in flight without a receipt (`runner.mjs:41-44`): a mined run seen through a lagging rpc never resets the weekly timer, a mined revert never starts the cooldown. (b) a raw send that reached the pool but errored on retry (timeout, `nonce too low`) is `send_error` with no in flight record (`chain.mjs:147-152`, `runner.mjs:142-147`); the tick moves on and the next tick may resend. (c) SIGKILL (kill_timeout 30 s) between broadcast and `save()` has the same effect | on "nonce used", poll the receipt a few more times and settle it; record in flight before the raw send (hash is known after signing) and clear it on a definite reject |
| KR-12 | low | LAYER rate is applied to the whole router balance, a partial fill always misses it | the keeper sets `minOut = bal * rate` (`CollectFlushKeeperLayer.sol:107`) while the rate is quoted from the consumed `wBurn` of a clamped (1% impact) partial fill. a router big enough to partial fill skips step 5 every run, which feeds KR-01. not proved on a fork | quote per router and scale by `wIn`, or pass the rate to a keeper that checks out per weth consumed |
| KR-13 | info | image and secret hygiene | `FROM node:22-alpine` not digest pinned (`Dockerfile:4`); `.dockerignore` sends all of `keeper/` (a stray `keeper/.env` reaches the remote builder, not the image); an out of range key (0 or ≥ n) prints its decimal value in the `fatal` log via viem's message (`config.mjs:89`, `index.mjs:60`); `KEEPER_PRIVATE_KEY` stays in `process.env` for the process life | pin the digest; add `keeper/.env*` to `.dockerignore`; wrap `privateKeyToAccount` with a fixed message; `delete process.env.KEEPER_PRIVATE_KEY` after load |
| KR-14 | info | cadence differs from the runbook | runbook: 111 hourly, LAYER daily, "skip if pending is worth less than the gas unless the timer is due". runner: every 10 min for all, no value vs gas check (`keeper-runner.md` says thresholds cover it). this is what turns KR-01 into a drain | see KR-01 |

## min out, worst case per run

| keeper | honest rpc | lying rpc or no quote |
|---|---|---|
| 111 | 100 bps of the convert below the simulated output, plus drift while the tx waits (minOut is absolute, up to 30 min in flight). private relay when set | `run(true, 0)` (KR-02). the v1 swapper's 80% floor and price limit are computed from `getSlot0` inside the convert (`FeeAutoSwapper.sol:357, 386-390`), after a same block front run, so they do not bound a sandwich. loss up to the value of one convert step (`min(balance, maxStepIn)`) minus the attacker's round trip fees. today one convert is about 0.00065 eth (fork, 13,404 coin) |
| LAYER | 200 bps below the simulated rate, public mempool | rate 0: routers with an owner floor keep `floor * bal`; router 0x0EB2 gets minOut 0, its 1% impact clamp and 80% spot floor read the moved spot. loss up to that router's weth balance minus attacker fees |
| v2 | 100 bps on the smallest swapper, the others less protected (KR-03), public mempool | minOut 0: the v2 swapper's `spotFloorBps` (default 9500) and impact cap read the moved spot too (`FeeAutoSwapperV2.sol:216-221`). loss up to `min(balance, maxStepIn)` per swapper minus attacker fees |

the helper floors stop a griefer passing 0 at a fair price, not a sandwich. the runner's minOut is the only absolute bound, and its source is one rpc.

## holds

| claim | checked |
|---|---|
| key never logged or served | config errors do not echo the key (`config.mjs:86-88`); the viem account object holds no key (`JSON.stringify(account)` checked); logs and `lastError` use `shortMessage`, which omits the rpc url (checked: full `message` contains the url path with its api key, `shortMessage` does not); `/healthz`, `/metrics`, the state file carry the address only; secrets via `fly secrets`, no build args, the image copies only `*.mjs`, `abi/`, the registry |
| a bad rpc cannot change what is signed | `to` is the registry or env keeper address, data is `encodeFunctionData` of `run` or `collectAndForward` from the committed abi, value 0, chain id from the registry (must be 1, `config.mjs:83`) and preflight compares it to the rpc (`app.mjs:28`), signing is local (`chain.mjs:141`). the rpc controls nonce, quote, preview and receipts only |
| gas and fees bounded per tx | gas limits are constants (1.2M, 3.5M, 2M), never estimated; `maxFeePerGas = min(2 base + priority, MAX_GAS_GWEI)`, priority capped at `MAX_PRIORITY_GWEI` and floored at 0, skip when `base + priority > cap` (`decide.mjs:54-63`). worst single tx: 3.5M x 30 gwei = 0.105 eth |
| owner key refusal | refuses 0xCB43…17F9 with the committed registry (`reg.owner` plus 22 contract owner fields) |
| one tx in flight | in flight saved before the wait (`runner.mjs:149-152`), the next tick or process settles it first, the whole tick waits |
| revert handling | never resent in the tick, 1 h cooldown from `sentAt`, two in a row alerts, reason replayed |
| private relay has no silent runtime fallback | a non transient relay error is `send_error`, the tx is not resent publicly (`chain.mjs:146-152`) |
| DRY_RUN=1 sends nothing | returns before `io.send` (`runner.mjs:136`) |
| corrupt or foreign state refuses | throws, the process exits instead of starting empty (`state.mjs:16-17`) |
| 429 and transient errors | viem transport retry plus outer backoff with jitter; anything mentioning revert is never transient (`chain.mjs:11-24`) |
| `eth_simulateV1` absent | falls back to `eth_call` for the revert check and sends `doConvert false`, never an unquoted convert (but see KR-01) |
| thresholds | 111 `> 0.02 eth`, `> 10,000e18`, `escrowed > 0.05 eth`, weekly; LAYER router `>= threshold` with a `> 0` guard, combined `>= 0.01 weth`; v2 `> 0.02 eth`, `> 10,000e18`, weekly. match RUNBOOK actions 3 and 2b and the README |
| watchdog | exits after `max(3 x interval, receipt timeout + 2 x interval) + 300` s (2,100 s default) without a finished tick; fly restarts it |
| metrics labels | quotes, backslashes and newlines escaped (`metrics.mjs:5`); label values are keeper ids, result names, event names |
| dependency surface | viem only, exact pin, lockfile, `npm ci --omit=dev --ignore-scripts`, audit clean; runs as `node` after the chown |
