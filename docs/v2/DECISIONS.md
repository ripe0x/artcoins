# artcoins v2 — decisions made unattended

each entry: what was decided, the alternatives, why. review and overrule as you like.

| # | decision | alternatives | why |
|---|---|---|---|
| D1 | tests in this session run against uniswap v4 deployed from the pinned `lib/v4-core` / `lib/v4-periphery` source on a local anvil/forge evm, not a mainnet fork. fork suites are kept and gated on `MAINNET_RPC_URL`. | wait for an rpc; mock v4 | the sandbox denies every rpc host. v4 from source is the real code, not a mock; fork runs are a one command re-run once an rpc is set. |
| D2 | registry fields that need chain reads (bytecode match, owner, deprecated flag, deploy block) are filled from broadcast records and the brief, and tagged `chainVerified: false` until `script-js/verify-registry.mjs` is run with an rpc. | leave the registry empty | a registry with provenance tags is more useful than none; the verifier is the source of truth. |
| D3 | work on branch `v2`, mirrored to the session branch `claude/gallant-dirac-3dezg7`. | only the session branch | the brief names `v2`; the harness names the session branch; pushing both costs nothing. |
| D4 | `docs/` was gitignored; `docs/v2/` is now un-ignored so the v2 docs ship with the pr. | keep docs out of git | the brief asks for docs in the repo. |
| D5 | `MAINNET_RPC_URL` defaults to tenderly's public gateway (https://mainnet.gateway.tenderly.co) in .env.example, foundry rpc_endpoints, ci, verify-registry and the fork test docs. | require a keyed provider | owner's instruction; keyless, rate limited but enough for verification and fork tests. |
| D6 | v2 lives under `src/v2/` plus `src/Constants.sol`; v1 sources stay untouched as the record of deployed bytecode. | edit v1 in place | live coins depend on v1 bytecode; a clean v2 tree is easier to audit and to diff. |
| D7 | frozen vs owner mutable boundary: as in docs/v2/DESIGN.md section 2. per coin state on hook and locker is written once in the launch tx and has no writer afterwards (locker slot admins, pool extension swap, referral cap setter, sniper recipient setter all removed). owner keeps global pointers, bounded tunables and rescue of unowed balances. | keep v1 slot admins and token admin setters | principle 1 and 3; the 111 locker split is already frozen in practice (slot admin dead). |
| D8 | tax rate stays token admin tunable within a frozen cap (`taxBpsMax`). | frozen rate | 111 relies on it; the cap is the frozen part. |
| D9 | venue list is add only, held by a `venueAdmin` set at launch (default token admin), renounceable. | launcher owner adds venues via a registry | a token must not depend on mutable factory side state. |
| D10 | tax sink must be the dead address or the pool's bounty recipient, immutable, echoed in the launch event. | any address | an arbitrary sink is a hidden fee recipient; 111's sink is a contract today and is documented as such. |
| D11 | skim over charge on price limited partial fills is refunded via the escrow to the PoolManager caller. | revert partial fills | reverting breaks price limited burners and aggregators. |
| D12 | taker binding of the tax exemption is to source (PoolManager only), tx, direction and cumulative realized amount. true taker binding is impossible in v4 (take recipient chosen after the hook returns). | require recipient in hookData | breaks aggregators and routers. |
| D13 | escrow claims stay permissionless with a `selfClaimOnly` opt in that the fee owner sets for itself; `FeeAutoSwapperV2` opts in at construction. | self claim only for contracts | a treasury that cannot call out would be stranded. |
| D14 | hook size: NO delegatecall cold module. one hook contract, surface trimmed (open pools, lp fee mev paths, sniper recipient setters, per pool setters, static fee variant dropped). ci gate fails under 1,024 bytes of headroom at optimizer_runs 200. measured v1 hook is 20,558 bytes at runs 200 (the foundry.toml "29 bytes headroom" note is stale and is corrected). | immutable cold module via fallback (architect's pick) | 4k of headroom plus 5k of removed surface is enough; a delegate module is a second audit surface and a storage layout hazard for no size need. |
| D15 | baseline skim cap 10% of volume; anti sniper starting skim cap 90%. | keep 90% baseline | 111 uses 6%; a 90% baseline is a rug lever. |
| D16 | referral leg push failure credits the referrer in the escrow. | fold into protocol (v1) | the referrer earned it. |
| D17 | v2 pools are native eth paired only. | allow weth | 111 is native; weth doubles the test surface. |
| D18 | stream probe: low level call, gas capped (default 150k, owner bounds 30k..500k), return ignored, only when the recipient has code and >= `preSwapStreamMin`. push gas default 50k (bounds 10k..150k). | uncapped high level call (v1) | b2 root cause. |
| D19 | fee receivers get events only, no callback. | erc165 opt in callback | callbacks are how recipients brick pools. |
| D20 | every owned v2 contract uses Ownable2Step; single eoa owner, no multisig, no timelock. | plain Ownable | one key as instructed, but a typo in transferOwnership must not lose the stack. |
| D21 | LAYER legacy hook `protocolFeeNumerator` stays 0; documented in the runbook as the one live fee lever on LAYER. | raise it | not asked. |
| D22 | v1 lp fee mev modules (LinearFees, DescendingFees, SniperSteppedFees, TimeDelay) are not shipped in v2; only the skim module. the hook caps every module window at 180 minutes regardless of what the module reports. | port them | the current stack uses skim; fee path modules were the b7 cap mismatch. |
| D23 | escrow core depositors (hook, locker) cannot be removed; others can. owner rescue is limited to `balance minus totalOwed`. | free removal | removing a core depositor bricks the push fallback. |
| D24 | hard transfer mode: token reverts any transfer from or to the PoolManager unless the hook granted a same tx, per direction allowance; transfers touching a listed venue revert. erc6909 claims on side pools inside the PoolManager are accepted as a residual and documented. | block claims too | impossible from the hook of another pool. |
| D25 | keepers: a `CollectFlushKeeperV1` pinned to the live 111 locker, coin and fee swapper (collectRewards then flushPaired then optional convert, forwards rewards to the caller); a generic `ArtCoinsKeeperV2` for v2 coins. | none | the brief asks for it; it narrows but does not close the live stranding window. |
| D26 | the attached `origin` is the PUBLIC repo ripe0x/artcoins, so branch `v2` and the draft pr (review docs with findings on live contracts, proof tests) are public from the first push. i pushed as instructed ("push often, open a draft pull request"). nothing found is profitable to an attacker (griefing and stranding only, no fund theft), but review this first thing. | keep v2 local and leave a git bundle | the brief's instruction was explicit; a bundle would have blocked ci and the pr. if you disagree, delete the remote branch and i will re deliver as a bundle. |
| D27 | v2 ports the generic deploy time extensions (airdrop, vault, dev buy) with their review fixes as package e1. the LAYER specific extensions (liquidity layer auto forward, counter pool, sprite and onchain renderers) and the auto burn pool extension are not ported; they stay v1 for LAYER only. | port everything | they are LAYER specific, reverting on native pools, and nothing on the current or v2 stack uses them. |
| D28 | v2 locker keeper reward starts at 0 bps (the deploy script sets it; the live locker runs at 0); the owner can raise it up to 2% later. | 50 bps default | matches live behavior; a reward is only needed once third party keepers are wanted. |
| D29 | locker pushes use a fixed 150k gas cap (`PUSH_GAS_MAX`); the hook's push gas stays owner tunable within bounds. | tunable on the locker too | the locker is not on the swap hot path; one fewer setter. |
| D30 | token strings are bounded at construction and in every setter: name 64 bytes, symbol 16, image url 2,048, metadata 4,096, context 4,096. renderers cap urls at 2,048 and descriptions at 4,096. | unbounded (v1) | the 8m render gas budget is only provable if the token bounds its own strings; big images belong in renderers or off chain, not in a url field. |
| D31 | `processBurnOpenTab` on the v2 burn router is gated to an owner set `openTabCaller` (default none). nothing in v2 calls it since the auto burn extension is not ported (D27). | remove it | keeps the interface stable; a gated dead path is harmless and a future extension can use it. |
| D32 | the 80% spot floor on the swapper and burn router becomes owner tunable per contract within `SPOT_FLOOR_MIN_BPS = 5_000` and `SPOT_FLOOR_MAX_BPS = 9_500` (added to Constants, not hashed). | fixed 80% | a pool with a 10% lp fee plus a 10% baseline skim can never clear an 80% floor, stranding coin side fees with no owner lever. |
| D33 | per coin fee swappers and the protocol fee controller must be escrow depositors for their push fallback; the deploy script adds the controller, and the runbook adds a step "add the coin's fee swapper as an escrow depositor at launch". | let non depositors store fees | an open `storeFees` would let anyone spam escrow accounting. |
| D34 | the token nets PoolManager inflows against the outstanding same tx outflow grant (HARD) and budget (VENUE): coin flowing back into the PoolManager first cancels unused outflow allowance before counting as an inflow grant. closes the hook's three residuals (remove then re add, unused grants, buy then sell back in one unlock). | accept the residuals | cheap, token side only, no interface change. |
| D35 | the bounty stream probe keeps 150k gas default (owner tunable 30k..500k). a frozen recipient can spend that gas inside the unlock but cannot revert or reorder the swap. | lower to 50k | the live 111 recipient's streamForward cost is unmeasured; the owner can lower it once measured. |
| D36 | deploy order rule: the escrow adds the hook and locker as core depositors before the hook's `setFeeEscrow` and the locker's `setFeeEscrow`; the controller and every per coin fee swapper are added as depositors (D33). the deploy script asserts this. | constructor checks | the hook's constructor cannot see an escrow that does not yet know it. |
| D37 | solady's fixed infinite Permit2 allowance stays on the token; the locker skips its erc20 approve and reset when `allowance(locker, permit2) == type(uint256).max`. | override the token to disable it | the token behavior is standard and saves gas for every holder; the locker is the only caller that cared. |
| D38 | the token deployer is deployed as its own contract and bound to the factory (`ArtCoinsDeployerV2(factory)` constructor arg, `factory.setTokenDeployer(address)` owner only). the factory no longer embeds it with `new`. | keep embedding | factory initcode was within 1.8k of the 49,152 limit at the default profile, and the deployer runtime was 55 bytes over 24,576 there; splitting removes both cliffs and keeps the deployer replaceable (principle 2). |
| D39 | swapper `convert` gets the burn router's protections: a price impact cap (`maxImpactBps`, default 100, owner tunable 25..300 via the existing burn constants), one convert per block, default spot floor raised to 95%, and the step size bounded by `maxStepIn`. sandwich loss per call is bounded by the impact cap plus fees instead of 20%. | permissioned convert | permissionless keepers are the point; bounding the loss is enough once the reward is small. |
| D40 | burn router: the hook's skim refund credited during a burn is excluded from the output floor check and from the keeper reward base, and `maxBurnPerCall` (owner tunable, default 5 eth) caps the eth per burn so a large balance drains over blocks instead of reverting forever. | leave as is | review b proved a router with 50 eth could never burn again on 111 style fees, and eth sent to it is unrescuable. |
| D41 | no recipient code runs during a swap. fee legs are pushed with a 2,300 gas stipend only (enough for an eoa or an empty payable receive, not enough to call the PoolManager), escrow on failure; the `streamForward` probe is removed from the hook. contracts that need to react to fees (the credits engine treasury, the 111 style bounty recipient) pull from the escrow or are poked by the keeper outside the swap. | keep gas capped pushes (50k) | review v2h-01: with the PoolManager unlocked, 50k gas is enough for a recipient to `take` 1 wei and make the user's swap revert at settlement (a sell only honeypot), or to spend the buyer's tax exemption. the only safe amount of recipient code during a swap is none. |
| D42 | the skim over charge on price limited fills is refunded inside the swap through the afterSwap return delta to the swapper, not through the escrow. the escrow path stays only as a fallback if the delta cannot be applied. | escrow refund (DESIGN b3) | review v2h-03/06: escrow refunds to a router are stranded and an exact out seller can be left owing eth until the refund lands. |
| D43 | HARD mode: liquidity removals are always reported to the token; the same tx add then remove marker applies to VENUE attestation only. | marker in both modes | review v2h-02 proved a free inflow allowance in HARD mode. |
| D44 | self referral through a router is accepted and bounded by the frozen per pool referral cap (max 1% of volume) and the factory injected referral payout. | require a signed referrer | not worth the ux cost; the cap bounds the leak. |
| D45 | v2 contracts ship built at the `ci`/`tune` profile (optimizer_runs 200). sizes at the default profile (runs 20,000) are informational; the deployer is 55 bytes over the runtime limit there and that is accepted. | shrink the token to fit both | the deploy script and ci pin the profile; a default profile deploy would already fail its own size check. |
| D46 | when a coin has a tax mode (VENUE or HARD), liquidity on the canonical pool can only be added by allowlisted launchers (the locker at launch). third party lp goes to side pools (taxed in VENUE, blocked in HARD). liquidity removals never attest budget or grant flows; only swaps do. NONE mode keeps open lp with no attestation. the same tx marker (b1) becomes unnecessary and is removed. | per tx one way lock on liquidity direction (reviewer's fix) | review v2a-01: remove, side buy, take as erc20, mint own principal as erc6909 claims needs no re add, so a direction lock does not close it. no lp principal, no cover. |
| D47 | tax exempt entries are limited to an owner managed `exemptAllowlist` on the factory (escrow, locker, hook, the coin's own fee swapper and burn router once deployed, vaults and airdrops registered as extensions). a deployer cannot exempt an arbitrary contract. the token keeps its contracts only rule as defense in depth. | any contract (v1 and t1) | review v2a-02: a deployer's own forwarder contract buys untaxed. |
| D48 | `venueAdmin` gets `transferVenueAdmin(address)` (venue admin only) and does not follow `updateAdmin`. | tie it to the token admin | separate roles stay separate; renounce stays available. |
| D49 | keeper per step gas values are floors (`gasleft()` must exceed the floor) not caps on the call; the call gets all remaining gas. | hard caps | review v2a-05: a collect that grows past the cap would revert forever. |
