# artcoins UI

## What this is

`ui/` is the deploy/browse/swap web app for the artcoins token launcher —
deploy a new art coin, browse existing tokens, swap on their V4 pool, claim
an airdrop, and manage referrals. Stack: Vite + React 19 + wagmi +
RainbowKit + Tailwind v4 + react-router 7.

## Setup

```bash
cp .env.example .env
```

Then fill in `.env`:

- `VITE_WALLETCONNECT_PROJECT_ID` — **required**. RainbowKit needs a
  WalletConnect Cloud project ID to support mobile wallets; the app fails
  to start without it. Get one free at
  [cloud.walletconnect.com](https://cloud.walletconnect.com).
- `VITE_ALCHEMY_API_KEY` — **strongly recommended**. Used for RPC on
  mainnet and Sepolia. Without it, the app falls back to public RPCs,
  which rate-limit aggressively and can fail outright on the `getLogs`
  queries the token-list and fee-flow pages depend on. Get one free at
  [dashboard.alchemy.com](https://dashboard.alchemy.com).

```bash
npm install
npm run dev
```

## Runtime config

`ui/public/config.json` is runtime config for the deployed app — it's a
static asset that an operator edits and re-uploads, **without** a frontend
rebuild. Currently the only field is `defaultReferrer`: the address
credited as referrer when a visitor swaps without a `?ref=0x...` URL
parameter. A URL-attributed referral (`?ref=0xfriend`) always overrides
the default. Set `defaultReferrer` to the canonical protocol payout
address — the same address used for the team/creator fee and the
title-auction payout — so default-referrer revenue lands in one place.
The swap-fee hook bounds the referral cap to 250 bps (0.25%) per swap and
only credits a referrer when the pool's `permanentCollection` is either
unset (`address(0)` — generic artcoins coins, no gate) or reports
`acquisitionCount() > 0` (PC-style coins post-first-vault).

## Airdrop allowlists

`ClaimPage` (`ui/src/pages/ClaimPage.tsx`) fetches an allowlist for a token
from `/allowlists/<lowercased-token-address>.json` — e.g. for token
`0xABC...`, it fetches `/allowlists/0xabc....json`. Files live in
`ui/public/allowlists/` and are generated by `script-js/build-allowlist.ts`,
which writes to that path by default. These JSON files (addresses, amounts,
merkle proofs) are public data by design — anyone can compute a valid claim
proof from the on-chain merkle root anyway, so serving the file just saves
recomputation.

## Chain support

Mainnet and Sepolia. Contract addresses for both live in
`ui/src/lib/config.ts` (`MAINNET_ADDRESSES` / `SEPOLIA_ADDRESSES`) and are
kept in sync with Foundry broadcast output by
`script-js/sync-addresses.mjs` — see `script-js/README.md`.
